# ePeddlers Backend (PHP REST API)

PHP 8.2 + MariaDB/MySQL REST API for the La Carlota City Peddler Business Permit
Application system. Serves both the web app and the mobile app.

See `docs/` for architecture, the role/permission matrix, and the workflow.

## Prerequisites

- XAMPP with PHP 8.2+ and MariaDB 10.4+ (or standalone PHP + MySQL)
- The MySQL/MariaDB server running

## Setup

1. Copy the environment file and edit as needed:

   ```powershell
   Copy-Item .env.example .env
   ```

   Key settings: `DB_*`, `CORS_ALLOWED_ORIGINS`, `STORAGE_PATH`, `APP_DEBUG`.

2. Create the database and load schema + seed. From this folder:

   ```powershell
   $mysql = 'C:\xampp\mysql\bin\mysql.exe'

   # Fresh/reset database (DESTRUCTIVE — development only)
   Get-Content database\reset.sql  -Raw | & $mysql -u root

   # Schema
   Get-Content database\schema.sql -Raw | & $mysql -u root epeddlers

   # Reference seed (roles, permissions, fee/violation categories, settings)
   Get-Content database\seed.sql   -Raw | & $mysql -u root epeddlers

   # Generate + load development users with real bcrypt hashes
   C:\xampp\php\php.exe database\make_seed_users.php | Out-File -Encoding ascii database\seed_users.sql
   Get-Content database\seed_users.sql -Raw | & $mysql -u root epeddlers
   ```

## Run (development)

Option A — PHP built-in server (quickest):

```powershell
C:\xampp\php\php.exe -S 127.0.0.1:8099 -t public
# API base: http://127.0.0.1:8099/api/v1
```

Option B — Apache (XAMPP): point a vhost/alias at `epeddlers-backend/public`.
The included `public/.htaccess` routes all requests through `index.php` and
preserves the `Authorization` header.

## Smoke test

With the server running:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File database\smoketest.ps1
Get-Content _smoketest.txt
```

Expected: successful admin login, `/auth/me` resolves, bad login = 401,
unauthenticated `/me` = 401.

## Implemented endpoints

Auth & health:
- `GET  /api/v1/health`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/logout`
- `GET  /api/v1/auth/me`
- `POST /api/v1/auth/change-password`

Users (admin — `users.manage` / `users.view`):
- `GET  /api/v1/users` (search, status filter, pagination)
- `POST /api/v1/users` (returns one-time temp password)
- `GET  /api/v1/users/roles`
- `GET  /api/v1/users/{id}`
- `PUT  /api/v1/users/{id}`
- `PATCH /api/v1/users/{id}/status`
- `POST /api/v1/users/{id}/reset-password`

Applications — public:
- `POST /api/v1/applications` (create draft; returns Application ID + PIN)
- `POST /api/v1/applications/{code}/submit`
- `POST /api/v1/applications/{code}/documents` (multipart upload)
- `GET  /api/v1/track?code=&pin=` (applicant-safe status + timeline)

Applications — authenticated:
- `GET  /api/v1/applications` (search/filter/pagination)
- `GET  /api/v1/applications/{id}`
- `GET  /api/v1/applications/{id}/timeline`
- `POST /api/v1/applications/{id}/review`
- `POST /api/v1/applications/{id}/approve` (issues permit + creates peddler)
- `POST /api/v1/applications/{id}/reject` (reason required)
- `POST /api/v1/applications/{id}/return-for-correction` (reason required)
- `GET  /api/v1/documents/{id}/download` (access-controlled)

Dashboard & activity (admin — `reports.view` / `activity.view`):
- `GET /api/v1/dashboard/admin`
- `GET /api/v1/activity-logs` (search/date filter/pagination)

Inspections (`inspections.conduct`):
- `GET  /api/v1/inspections` (queue of applications pending inspection)
- `POST /api/v1/inspections`
- `GET  /api/v1/inspections/{id}`
- `POST /api/v1/inspections/{id}/submit` (advances workflow by recommendation)

Sanitary reviews (`sanitary.conduct`):
- `GET  /api/v1/sanitary-inspections`
- `POST /api/v1/sanitary-inspections`
- `POST /api/v1/sanitary-inspections/{id}/submit` (independent of inspection)

QR (`qr.resolve`):
- `POST /api/v1/qr/resolve` (returns permission-scoped peddler/permit info)

Peddlers:
- `GET /api/v1/peddlers` · `GET /api/v1/peddlers/{id}`
- `GET /api/v1/peddlers/{id}/permits` · `GET /api/v1/peddlers/{id}/violations`

Violations:
- `GET  /api/v1/violations` · `GET /api/v1/violations/categories`
- `POST /api/v1/violations` (`violations.record`)
- `GET  /api/v1/violations/{id}` · `PATCH /api/v1/violations/{id}`

Collections — arkabala (`collections.record`):
- `GET  /api/v1/collections` (history)
- `POST /api/v1/collections` (server-authoritative amount; idempotency via
  `X-Idempotency-Key` header prevents double collection)
- `GET  /api/v1/collections/fee-categories`

Treasury (`treasury.verify` / `treasury.reports`):
- `GET  /api/v1/treasury/dashboard`
- `GET  /api/v1/treasury/applicants` (search by Application ID / name, filter by type)
- `GET  /api/v1/treasury/payments/{id}` (charges + payment records + verification history)
- `POST /api/v1/treasury/payments/{id}/verify` (verify/reject; clears payment for final
  approval but does not issue the permit; corrections recorded as auditable reversals)
- `GET  /api/v1/treasury/collections` (search/week/status filters, pagination)
- `POST /api/v1/treasury/collections/{id}/reverse` (auditable, reason required)
- `GET  /api/v1/treasury/reports/weekly?week=YYYY-MM-DD` (viewable any day)
- `POST /api/v1/treasury/reports/weekly/generate` (Saturday-only, La Carlota time)

Reports (`reports.view`) — totals from DB, `?from=&to=` date range:
- `GET /api/v1/reports/applications`
- `GET /api/v1/reports/collections`
- `GET /api/v1/reports/inspections`
- `GET /api/v1/reports/violations`

Notifications (any authenticated user):
- `GET  /api/v1/notifications` (`?unread=1`; meta includes unread count)
- `POST /api/v1/notifications/read-all`
- `POST /api/v1/notifications/{id}/read`
